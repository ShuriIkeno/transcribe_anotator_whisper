# transcribe_annotator_whisper

音声インタビューを **文字起こし → 話者ラベル付け・誤字修正 → テキスト書き出し** するためのローカルツール一式です。

2つのスクリプトから成ります。

| スクリプト | 役割 |
| --- | --- |
| `transcribe.py` | [faster-whisper](https://github.com/SYSTRAN/faster-whisper) を使い、ディレクトリ内の音声を一括で文字起こし |
| `annotator.py` | 文字起こしと音声をブラウザ上で並べ、発話者ロールのラベル付け・誤字修正・書き出しを行うGUI |

最終出力は MAXQDA などに読み込める、行頭にロールを括弧書きしたシンプルなテキストです。

```
(インタビュアー) はい、ということでですね
(インタビュイー) よろしくお願いします
```

---

## セットアップ

Python 3.12 で動作確認しています。

```bash
python -m venv .venv
source .venv/bin/activate
pip install faster-whisper
```

- `annotator.py` は **Python標準ライブラリのみ**で動くため、追加インストールは不要です（`faster-whisper` は文字起こし用）。
- Whisperモデルは `./model/` に配置します（CTranslate2形式）。`recordings/` と `model/` は `.gitignore` 済みで、音声・文字起こし・モデルはコミットされません。

### モデルは `large-v3` を推奨します

`./model/` に何を置くかで、精度が大きく変わります。**`large-v3` を推奨します。**

実際のインタビュー音声（日本語・30分・5人）で比較した結果です。左は `large-v3-turbo`
（蒸留版。デコーダが32層→4層）、右は同じ音声を `large-v3` で取り直したものです。

| 発話 | large-v3-turbo | **large-v3** |
| --- | --- | --- |
| 人名 | チラケイト25歳です | **内田圭人**さん |
| 略語 | PTC**J**L / PTC**G**L と割れる | **両方 PTCGL** |
| 一般語 | 紙で読むのと**伝書籍**で | 紙で読むのと**電子書籍**で |
| 専門用語 | 山だったり**虎白のあり手**だったり | 山だったり**トラッシュ**だったり**手**だったり |

固有名詞・専門用語の誤変換は、多くがモデルを上げるだけで消えます。

モデルの取得（CTranslate2形式。`./model/` に置くか、シンボリックリンクを張ります）:

```bash
pip install huggingface_hub
python -c "from huggingface_hub import snapshot_download; \
  snapshot_download('Systran/faster-whisper-large-v3', local_dir='model')"
```

### 動く端末・動かない端末

`large-v3` は **2.9GB**（重みは float16）。`transcribe.py` は `compute_type="float32"` で
読むため、実行時は **6GB前後**のメモリを使います。

| 端末 | 可否 |
| --- | --- |
| NVIDIA GPU（VRAM 8GB以上） | `--device cuda` で快適。30分の音声が1分弱 |
| NVIDIA GPU（VRAM 6GB未満） | float32 では載りません。小さいモデルにするか、`compute_type` の変更が必要 |
| **Apple Silicon (M1〜M4)** | **`--device cuda` は使えません**。CPUのみで動きます（下記） |
| メモリ 8GB未満のマシン | large-v3 は厳しい。`medium` 以下を検討 |

**Apple Silicon では GPU を使えません。** `transcribe.py` が使う CTranslate2 に Metal 対応が
無いためです（実測: `ctranslate2.get_supported_compute_types("cpu")` は
`float32 / int8 / int8_float32` を返し、`"cuda"` は `ValueError`）。
動きはしますがCPU実行なので時間がかかります。Apple GPU を使いたい場合は
mlx-whisper など別系統のツールが必要です。

なお CPU では `int8` にすると所要メモリが約半分になり数倍速くなりますが、
`transcribe.py` は `compute_type` を float32 に固定しているため、
現状は使うにはコードの変更が要ります。

## 1. 文字起こし（`transcribe.py`）

音声（`.wav .mp3 .m4a .flac .ogg`）を入れたディレクトリを指定して実行します。

```bash
python transcribe.py recordings
# GPUを使う場合:
python transcribe.py recordings --device cuda
```

音声ファイルごとに、同じ名前で2種類のテキストが出力されます。

- `<名前>_timecoded.txt` … `[開始s -> 終了s] テキスト` 形式（アノテーターが読み込む）
- `<名前>_text.txt` … テキストのみ

例: `recordings/P7.m4a` → `recordings/P7_timecoded.txt`, `recordings/P7_text.txt`

## 2. アノテーション（`annotator.py`）

```bash
python annotator.py
# → http://127.0.0.1:8000/ をブラウザで開く

# オプション
python annotator.py --port 8001 --dir /path/to/recordings
```

`recordings/` 内の `*_timecoded.txt` を自動で一覧化し、対応する同名の音声を読み込みます。`127.0.0.1` のみにバインドするため、音声がLANに公開されることはありません。

### できること

- **タイムライン連動** — 再生に合わせて該当行がハイライト＆自動スクロール（追従ON/OFF可）。シークバーのクリック／ドラッグ、行の時刻クリックで頭出し。
- **話者ラベル（任意個数）** — ヘッダーの「話者」で人数を 2〜9 人から選べます。名前クリックで改名、×で削除、「＋ ロール」で個別追加。4人以上のときは行のボタンが番号だけになり、1行に収まります（番号はそのままキーボードの数字キー）。
- **話者分離の取り込み** — WhisperX や pyannote の結果を読んで自動割り当て（後述）。
- **誤字修正** — 各行のテキストを直接クリックして編集（編集済みは色でマーク）。
- **置換辞書** — 同じ誤変換を「誤 → 正」で一括置換（後述）。
- **セグメント分割 / 結合** — 1行が話者をまたぐとき、カーソル位置で分割（時刻は文字位置で按分）、上の行と結合。
- **行削除 / 元に戻す** — 削除・分割・結合は `⌘Z`（Ctrl+Z）または「元に戻す」で取り消し可能（最大100手前まで）。
- **再生速度** — 0.5〜2×。

### キーボード操作

| キー | 動作 |
| --- | --- |
| `Space` | 再生 / 一時停止 |
| `1`〜`9` | 現在行にロールを付与して次の行へ |
| `0` | ロール解除 |
| `J` / `K`（`↑` / `↓`） | 行を移動 |
| `Enter` | 現在行を編集 |
| `D` | 現在行を削除 |
| `R` | 現在行を頭から再生 |
| `←` / `→` | 3秒シーク |
| `⌘Z` / `Ctrl+Z` | 削除・分割・結合を取り消し |

### 話者分離の取り込み（自動で割り当てる）

話者分離の結果があれば、**全行の話者を自動で割り当てられます**。
手で1行ずつ付けるより圧倒的に速く、あとは間違いだけ直せば済みます。

収録と**同じ場所に同じ名前で**ファイルを置いてください。

```
recordings/P7_timecoded.txt     ← 文字起こし
recordings/P7.m4a               ← 音声
recordings/P7.json              ← 話者分離（WhisperX の出力）
```

対応する形式は2つです。

| 形式 | 中身 | 出どころ |
| --- | --- | --- |
| `<名前>.json` | テキスト＋話者＋単語時刻 | WhisperX（`--diarize` 付き） |
| `<名前>.rttm` | 話者区間のみ | pyannote、その他の話者分離ツール |

**RTTM** は NIST の Rich Transcription 評価で定められた、この分野の標準形式です。
テキストを持たず「誰がいつ喋ったか」だけを表すので、**別のツールで作った文字起こしに
あとから話者を乗せる**のに使えます。pyannote が `write_rttm()` で直接書けます。

```
SPEAKER <file-id> <ch> <開始秒> <継続秒> <NA> <NA> <話者ID> <NA> <NA>
```

ヘッダーの **「話者を読み込む」** を押すと、検出された話者の一覧が出ます。
ここで `SPEAKER_00` などに**名前を付けてから**割り当てられます。

```
SPEAKER_00 → 内田
SPEAKER_01 → 小平
SPEAKER_03 → インタビュアー
```

割り当ては **⌘Z で丸ごと取り消せます**。

#### 割り当て方（なぜ多数決なのか）

日本語は分かち書きしないため、WhisperX の `words[]` は**1文字ずつ**になります
（30分の音声で9,701件）。文字単位の話者ラベルはバタつくので、そのまま使うと
1つの文の中で話者が何度も入れ替わって使い物になりません。

そこで**行ごとに「重なった時間で重み付けした多数決」**を取り、1人に決めます。
行の時間と話者区間の重なりを話者ごとに合計し、最大の話者を採ります。

**2位と僅差だった行には印**（左端の橙色の線）を付けます。話者分離が迷った場所で、
実際に聞いて直すべき当たりどころです。実データ（30分・5人）では 889行中、
809行に割り当て・36行が迷いあり・80行が対応なし（発話区間の外）でした。

### 置換辞書（同じ誤変換をまとめて直す）

モデルを `large-v3` にしても、同音語・言い間違い・漢字の揺れは残ります。
同じ誤りが何度も出てくるとき、1件ずつ直すのは無駄なので、
**「誤 → 正」の対を辞書に登録して一括置換**します。

登録のしかたは2つあります。

**行を直したついでに登録する（おすすめ）**

行のテキストを直すと、その行に **「辞書へ」** ボタンが出ます。押すと、
直した部分だけが自動で切り出されて辞書に入ります。

```
小平倫太郎です  →  小平凛太郎です     と直して「辞書へ」
   ⇒ 「小平倫太郎 → 小平凛太郎」が登録される
```

1文字だけの違いのときは、**語のかたまりまで自動で広げます**。
「倫 → 凛」で登録してしまうと無関係な「倫理」まで置換してしまうためです。

**辞書を直接ひらいて登録する**

ヘッダーの **「置換辞書」** から一覧を開き、「＋ 行を追加」で足します。
各行の右には、**いま開いている収録の中で何箇所ヒットするか**が出るので、
広すぎる規則（意図せず大量にヒットする）にすぐ気づけます。

**適用**

「この収録に適用」で全行に反映します。結果は「置換 N箇所 / M行」と通知され、
**`⌘Z`（Ctrl+Z）で丸ごと取り消せます**。

置換は次の性質を持ちます。

- **長い語が優先** — 「ポケモンカード」と「ポケモンカードゲーム」の両方があれば長いほうが勝ちます
- **連鎖しない** — 「あ→か」「か→さ」があっても「あ」が「さ」にはなりません（1回だけ置換）
- **正規表現ではない** — `a.c` は `a`, 任意の文字, `c` ではなく、そのままの3文字にマッチします

**辞書はリポジトリ直下の `replacements.json`** に保存されます。`recordings/` は
`.gitignore` されていて共有できないため、意図的にここへ置いています。
チームで育てたい辞書なので、コミットして共有してください。

```json
{
 "replacements": [
  { "from": "こちらケイト", "to": "内田圭人" },
  { "from": "24人", "to": "24歳" }
 ]
}
```

別の辞書を使うには `python annotator.py --replacements path/to/other.json`。

### 書き出し

ヘッダーの「書き出し」で `recordings/<名前>_annotated.txt` を生成します（元の `*_timecoded.txt` は書き換えません）。

- **連続結合** — 同じ話者の連続行を1段落にまとめる。
- **時刻付き** — 各行の先頭に時間を付ける。
- 未ラベルの行は `(未設定)` で出力し、件数を通知します。

### 途中復帰

変更のたびに `recordings/<名前>.annot.json` へ自動保存します（アトミック書き込み＋離脱時の送信）。ブラウザやサーバーが落ちても、再起動して同じ収録を開けば続きから再開できます。

トランスクリプトから作り直したいときは、ヘッダーの「再読込」を使います（付与したラベルと編集は失われます）。

## ファイル構成

```
transcribe.py            文字起こしスクリプト
annotator.py             アノテーターのローカルサーバー（標準ライブラリのみ）
webui/                   アノテーターの画面（index.html / app.js / style.css）
replacements.json        置換辞書（誤→正。git管理して共有する）
model/                   Whisperモデル（.gitignore）
recordings/              音声・文字起こし・アノテーション（.gitignore）
```
